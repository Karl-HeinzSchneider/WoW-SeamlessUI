# Defaults audit

Audited on 2026-10-31 against `main` at `a92c64d`, including merged PRs #171 and #175.
All nine addons are inventoried. The [source inventory](defaults-inventory.md) lists every
literal page/schema default, its value and source line, plus default resolvers, reset consumers
and geometry setters. It contains 383 literal leaves/empty tables; empty schemas and reset
sentinels are deliberately included. Regenerate with `python src/audit-defaults.py`, then format
the Markdown with Prettier.

This is a source audit, not an in-game capture. No active SavedVariables, CVar values or frame
measurements were used to choose factory defaults. The limitations below are explicit: the
inventory is complete for these source categories, but it does not certify every historical
visual reconstruction or server gameplay estimate as a Blizzard factory default.

## Meaning of default

- **Suite default:** a deliberately authored value in `optionPages.*.defaults`, the database
  skeleton, or an owned feature's initialization. This is authoritative for the addon, even when
  its feature changes Blizzard's appearance. Profile reset restores the declared schema and
  refreshes modules through `Seamless/src/core/profiles.lua` and `core/ace.lua`.
- **Client default:** the default return from `C_CVar.GetCVarInfo`, an Edit Mode preset API, or
  the loaded client's explicit Lua/XML definition. A live getter is not evidence of a default.
- **Restoration snapshot:** pre-override state used to undo an addon change. It can legitimately
  contain another addon's changes and must not be used for default tooltips or factory resets.
- **Contextual native placement:** bags, aura-dependent cast bars and size-dependent ToT frames
  have different native anchors in different states. A reset can remove an override without a
  single fixed default coordinate. Unknown coordinates display **Not applicable**.

## Limits and explicit uncertainty

1. **Engine defaults:** the exported UI documents `GetCVarInfo` but does not contain the engine's
   complete CVar default database. The runtime API is the authoritative source, and no specific
   static true/false value is asserted for those engine-owned settings here. An unavailable
   default remains nil, never the current CVar.
2. **Native computed coordinates:** there is no complete exported default-position API for the
   target/focus spell bars or combined bags. Their tooltips intentionally remain Not applicable;
   native reset behavior is source-backed. No in-game sampling can remove this limitation.
3. **Historical unit-frame visuals:** `layout/geometry.lua` and generated `atlas.lua` contain
   deliberate fixed Beta/rounded reconstructions. The current client export verifies current
   Mainline/Camelot templates and the important restoration rules; it cannot independently prove
   every pre-70425 art/geometry choice. Existing `docs/unit-frame-layout.md` records the pinned
   70374/70425 source revisions and original art provenance. The local historical cache directories
   contain no source files. A complete historical reproduction certification needs those original
   source/art exports; this audit does not relabel the reconstruction as Blizzard factory data.
4. **Rested XP estimates:** the suite declares fallback cap 150% and rate 5% per eight hours,
   with Adventure-tree multipliers. The server's actual cap/accrual behavior is not defined by
   these exported UI files. The schema is authoritative only for the addon's fallback estimate,
   not a verified server gameplay default. Tooltips already describe the calculation as an estimate.

## Validation

Regression coverage includes all 458 editable controls loaded by the suite declaration harness
under customized profile values and changed live CVar returns; actual player-size default helpers
are loaded rather than replaced with sample values. Native frame page generation is mocked in
that declaration harness and is separately exercised by native-position/Edit Mode harnesses.
Dedicated regressions cover Damage Meter factory resets versus inheritance, false defaults,
preview sentinel isolation, nil default preservation, and bag/cast-bar native reset behavior.

Validation passed: `npm run check` (314 Lua files; its XML step skips the absent sibling export),
all 41 executable Lua harnesses including the legacy layout harness, eight Python unit tests,
and `npx tsx src/tests/sync-locales.ts`. A separate lxml run validated all four addon XML files
against the supplied Forever export's `Blizzard_SharedXML/UI.xsd`.

The installed Lua/luac version is 5.4.2; harnesses used `unpack = table.unpack or unpack`.
StyLua's configured `Lua51` syntax check passed, but execution with a Lua 5.1 interpreter was
not available. In-game execution and visual behavior remain untested here.

In game, verify tooltip labels and
storage markers in both settings windows, custom profile changes, ToT small/large focus, aura
and gamepad cast-bar placement, combined-bag layout/scale changes, and reset/revert in Edit Mode.
